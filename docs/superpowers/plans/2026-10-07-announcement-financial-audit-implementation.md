# 公告财务时点审计实施顺序

用户已确认对应设计。writing-plans技能仍不在可用技能目录，本文件记录实施顺序，不声称调用该技能。

1. 检查锁与运行进程；保存共同样本股票范围、输入/源码/原结果哈希。
2. 通过现有加密凭据机制测试普通forecast、fina_indicator、fina_audit接口；记录真实响应与权限错误，不打印令牌。
3. 新增独立审计工具和续跑入口。逐股限速、不可覆盖原始响应、超返回上限按日期细分、有限重试、失败留证；认证失败停止。核心源码不修改。
4. 对公告时点、重复/修订、单位转换及满页细分作必要测试。
5. 下载固定共同样本全部股票的2013—2020公告，报告期接口另从2012年底覆盖。若普通接口受阻，保留已完成缓存和确切原因。
6. 区分API报告的公告日与原文核验的公开日，输出覆盖、版本冲突、候选证据索引及固定核验清单。未核验原文的记录不得标记为可信历史可用。
7. 按固定抽样、冲突和亏损股范围检索公司原文，记录取得或失败。复核全部旧结果哈希并报告审计限制。
