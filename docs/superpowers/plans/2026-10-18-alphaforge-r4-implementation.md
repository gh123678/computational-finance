# AlphaForge r4 实施与独立核验顺序

日期按客户端北京时间2026-10-18。用户在展示完整r4方案后明确回复“批准”，授权实施该固定实验；设计文档和上轮证据中的“待批准”是历史快照，保留原字节。本计划不更改设计边界，也不再次索取同一授权。

设计：`docs/superpowers/specs/2026-10-18-alphaforge-account-scope-r4-design.md`。brainstorming的设计批准关卡已满足；引用的writing-plans技能在本机技能目录未找到，以下手工形成同等可审阅实施计划，不因此停止已授权工作。

## 一、冻结前工程

1. 核对进程、锁、磁盘；保护原1924项、r3的105项及补证493项清单和原源码。仅新增r4模块、测试、计划和报告。
2. 构造独立证据映射：3项核对普通分派、600480仅日期配股覆盖、9股带公开日的官方非交易状态。保留来源路径、指纹、落款/公开/生效/结束区别和不确定性；不修改旧数据，不增加认购条款。
3. 实现实际敞口与拟成交守卫。空仓零历史权益；股份、待上市股份、尚未执行权益、应收分别记录。仅为实际价格敞口保存账本价格，独立原价历史仍全量保留。形成至执行和真实持仓参考断点仍停；无价需当日S或当时已知官方状态；未知/特殊/不相邻停牌权益仍停。
4. 独立适配器保留原Ledger及execute_order现金、股数、税费与容量公式。只改变已批准保护范围、缓存范围和缺报价目标的明确拒单记录；不换股、不重算目标。
5. 边界测试覆盖设计列出的反例；另外由独立审阅者检查经济义务、未来信息、全量库存与账户准入的区别。审阅中发现工程错误先修复并测试，不带着已知错误启动。

## 二、单次冻结与准备核验

1. 新建D盘独立r4目录与C盘junction；C/D均须至少6GiB。
2. 所有运行/核验共用独占锁；阶段单次写入，不重复启动。绑定源码、核心、批准设计/计划、r3准备输入、补证清单与使用文件的哈希，归档源码快照。
3. 准备仅引用/逐字复制已核验r3的273794形成键、154期、两份计划、R_week诊断和原价，不重训/重算因子或标签。保留全2806×790库存及16441失败，market_inventory_complete=false。
4. 独立核验准备相等、事件映射、来源指纹及空仓契约后，才签发conditional_account_attempt_allowed；不是全市场认证。

## 三、固定账户与停止规则

主路径0/10/30bp，然后对照0/10/30bp；同100万元与790个账户日。任一真实数据/权益失败立即终止整组六账户；未开始组保留not_started。失败当日保留守卫轨迹、账本快照、已完成日的净值/订单/权益和完整异常，不以部分结果声称完成绩效。

运行中只检查进度，不编辑其冻结源码/输入/状态。工程异常另留完整证据，须独立工程修复版本且不改变规则；数据失败不盲重试。任何新缺项不现场补证放行。

## 四、独立核验与报告

从订单和原行动重建逐日现金、已交割股、待上市股、应收、成本、陈旧估值和跨年；核验守卫逐日输入/判定、缺价解释、源日期与拒单。仅六组完成可签发全量账户核验与12跨年成功。

固定六项数值条件只在六组完整后评估；冻结IC单列为参考诊断，不能代替收益。部分失败的剩余关卡记未评估，不输出虚假的全量通过。最终交付明确终态、源映射/保护范围比较、真实失败和剩余限制；即使数值通过，实盘仍为blocked_by_unverified_data_and_forward_validation。
