# 金融插件实测体检报告（wind-allskill 为主，ifind / dongcai 对比）

- 测试时间：2026-09-28（交易日，盘中 13:00–13:40）
- 测试方法：通过各插件自带 CLI 直接构造调用，共 71 次（wind 63 个用例 + 1 次冒烟，ifind 4 次，dongcai 3 次）
- 原始日志：`results/` 目录下每个用例的 `.out` / `.err` 与 `summary.tsv`
- wind 用例结果：53 成功 / 10 失败（其中 9 个是刻意构造的负向用例，1 个为契约文档缺陷导致）

---

## 一、P0 数据正确性（最优先修）

### 1. 未知代码静默错配到无关标的（wind）
- 用例 X12：`get_stock_price_indicators` 传 `999999.SH`（不存在的代码），**成功返回** `93.790, BJ.N`——后端把未知代码模糊匹配到了一只不相干证券，CLI 层没有任何校验或警告。
- 风险：agent 会把错误标的的数据当成用户所问标的的数据写进答案，且无法察觉。
- 建议：CLI 在返回前比对请求 `windcode` 与响应 `wind_code`，不一致时输出显式警告（如 `"warning":"requested 999999.SH but got BJ.N"`）；NL 工具同理应提示实体解析结果。

### 2. 风险指标数值可疑且无口径标注（wind）
- 用例 S21：`get_risk_metrics` 返回贵州茅台"过去1年 BETA = -0.3242、波动率 = 1.4141"。茅台相对主流基准的 Beta 历史上显著为正，年化波动率通常在 20%–35% 量级，这两个值的口径（基准指数？年化？单位是小数还是 %？）均未标注，且数值本身存疑。
- 建议：返回字段中强制携带基准、窗口、年化方式、单位；后端复核该指标计算链路。

## 二、P1 错误处理与可用性

### 3. 错误分类系统性错位（wind，出现 4 次，影响面最大）
后端返回空数据或纯文本错误时，CLI 一律归为 `NETWORK_ERROR`，agent_action 误导调用方去"检查本机网络"：

| 用例 | 实际情况 | 后端原文 | 被错分为 | 应为 |
| --- | --- | --- | --- | --- |
| X07 周末查分钟行情 | 非交易日无数据 | `EMPTY_DATA` | NETWORK_ERROR | NO_RESULTS |
| X13 未来日期 K 线 | 无数据 | `EMPTY_DATA` | NETWORK_ERROR | NO_RESULTS |
| E06 宏观缺时间范围 | 参数缺失 | "observation或者[beginDate、endDate]必须填一个" | NETWORK_ERROR | PARAM_VALIDATION_ERROR |
| A01 债券当日成交排名 | 未入库/无数据 | "没找到数据" | NETWORK_ERROR | NO_RESULTS |

其中 A01 直接违背了自家契约——`analytics.md` 明确写了债券排名空数据"视为 NO_RESULTS"并给出话术，但 CLI 的错误映射把它归成了网络错误。
- 建议：把 `EMPTY_DATA` 和后端非 JSON 纯文本（"没找到数据"/"必须填一个"等）分别映射到 `NO_RESULTS` / `PARAM_VALIDATION_ERROR`，agent_action 给出对应修复指引。

### 4. 日期倒置未被本地拦截（wind）
- 用例 X14：`begin_date > end_date` 时本地校验放行，后端返回泛化的"服务暂时不可用，请稍后重试"（归为 NETWORK_ERROR）。
- 建议：本地校验日期先后关系，直接报 `PARAM_VALIDATION_ERROR`。

### 5. server_type 校验不一致（wind）
- 用例 X02：不存在的 `equity_data` 被**静默改路由**并成功返回数据；而用例 X01 中错误 tool 名会正确报 `ROUTE_ERROR`。
- 静默改路由会掩盖 agent 的路由错误（也可能是有意设计）。建议：至少输出 `"notice":"server_type equity_data 不存在，已按 tool 名路由到 stock_data"`，让行为可观测。

### 6. dongcai-mx-data 当前完全不可用（环境级）
- 连续 3 次调用均失败：`SSL: UNEXPECTED_EOF_WHILE_READING`，且错误是原始 urllib 异常字符串——没有结构化错误码、没有重试指引。同网关的 wind / ifind 同一时间正常，疑似 dongcai 端点或凭证配置问题。
- 建议：排查 dongcai 网关链路；同时给 CLI 加结构化错误输出（对照 wind 的 error envelope 设计）。

## 三、P2 文档与契约一致性（问题最密集的区域）

### 7. 宏观域文档整体过时（wind）
`tool-contracts.md` 的"宏观工具"章节写的是 `get_economic_data` + `metricIdsStr` + `freq/magnitude/currency` 参数——**这个工具不存在**（用例 E05 返回 ROUTE_ERROR）。真实契约是 `economic.md` 的 `search_economic_indicator` / `query_economic_indicator_data`（用 `question` + `beginDate/endDate/observation`，实测均正常）。SKILL.md 顶部的范围表也仍写着 `get_economic_data`。
- 建议：以 `economic.md` 为准重写 tool-contracts.md 宏观章节和 SKILL.md 范围表。

### 8. K 线参数三重矛盾（wind）
- 日期格式：SKILL.md / tool-contracts.md 要求 `yyyyMMdd`；stock/fund/index.md 写 `yyyy-MM-dd`（实测两种都接受，用例 S06/S07 结果一致）。
- `period` 枚举：tool-contracts.md 写数字 `"1".."15"`；域契约写 `"1min"/"1d"/"1w"`（实测 `"11"` 与 `"1w"` 结果完全一致）。
- 复权参数名：tool-contracts.md 写 `aftime`（"0"/"1"）；域契约写 `aftype`（0/1/2 三值）。实测两者都不报错，但**无法从输出判断哪个真正生效**——很可能其中一个被静默忽略，这比报错更危险。
- 建议：统一为一套写法（推荐与后端原生枚举对齐），另一套在 CLI 归一化层兼容并在文档中标注"兼容别名"。

### 9. `indexes` 必填性文档错误（wind）
stock/fund/index.md 写 `indexes` "否（有默认值）"，实测省略直接报 `PARAMETER_ERROR - Missing required parameters: indexes`（用例 S02）。要么 CLI 补默认值，要么改文档。

### 10. 成功路径的包络与文档不符（wind）
`error-codes.json` 声称"成功路径不返回 envelope，直接 stdout 输出纯数据"。实际输出是 MCP 风格的 `content[0].text`，且 text 里是**三层转义**的字符串（JSON 套字符串化字典套转义 JSON）。agent 每读一次结果都要解三层，token 浪费明显。
- 建议：CLI 在 stdout 直接输出解包后的纯净 JSON（`is_success / data_preview / notice / csv_path`），更新 error-codes.json 的 envelope_contract 描述。

### 11. 数据落盘位置与预览截断（wind）
`data_preview` 只有前几行，完整数据在 CSV；CSV 落在 `~/.cache/wind-allskill/csv/`（工作区之外）。`notice` 没有标注总行数，agent 不知道预览被截断了多少。另外 notice 文案有格式问题：`...csv.If the user has the need...`（缺空格，且 ifind 同款）。
- 建议：notice 中加 `total_rows` / `preview_rows`；支持 `--output-dir` 把 CSV 落到当前工作区。

### 12. 其他文档残留与矛盾（wind）
- `error-codes.json` 里保留 `SETUP_ERROR / setup-key / open-portal` 章节，与"本插件不持有任何密钥"的门禁并存，容易误导 agent 去尝试配置流程。
- 域契约写 `windcode` "多个用英文逗号分隔，单次最多 50 个"，SKILL 层禁止——这是 CLI 有意收紧，但应写明"后端支持批量，CLI 层强制单标的"，避免读者困惑。
- 基金同类排名只给名次不给分母（用例 F05 返回"近一年同类排名 1501"，无总数）。

### 13. 范围门禁只在文档层（wind）
SKILL.md 声明外汇等资产"范围外直接拒绝"，但 `EURUSD.FX` 照常返回数据（用例 X06）。如果拒绝是硬要求，需要在 CLI 层做资产类别拦截；否则文档措辞应软化。

## 四、ifind 对比发现

- **接口发现机制好**：`describe` 动态返回完整 API 文档；调错 API 名时错误信息直接列出全部可用 API（比 wind 的 ROUTE_ERROR detail 更实用，值得借鉴）。
- **文档内部矛盾**：ticker format 章节写美股后缀 `.O/.N`，`ifind_get_stock_realtime_price` 章节又写美股用 `.US`（AAPL.US）。
- **每个 API 都强制要求 agent 传 `file_path`**——比 wind 的自动落盘繁琐，同家族插件 UX 不一致，建议统一。
- 文档拼写错误若干（如 "ustomizable"、畸形示例 `'2021231'`）。
- 与 wind 同款 notice 文案问题（"csv.If the user…"）。

## 五、做得好的地方（建议保持）

1. **标的归一化健壮**：`NVDA`→`NVDA.O`、`700.HK`→`00700.HK`、`HSI`→`HSI.HI`、ETF 代码从 stock_data 自动改路由 fund_data、中文名（"贵州茅台"）直接可解析——全部实测通过。
2. **输入宽容度好**：日期 `yyyyMMdd` / `yyyy-MM-dd` 双格式、`period` 数字与字符串双枚举、指标别名归一（`pe_ttm`→`市盈率(TTM)`）都工作正常。
3. **本地拦截清晰**：逗号拼接 / 数组形式的多代码 windcode 在本地就被拦下，错误信息明确。
4. **NL 工具成功率高**：本轮 21 个自然语言工具调用全部成功（档案、财务、股东、事件、技术、基金业绩、指数分位、债券、新闻、公告等）。
5. **延迟可接受**：绝大多数调用 1–4 秒；最慢的是 analytics 兜底（9.8s，失败）和事件查询（7.3s）。
6. **错误码字典 + agent_action 的设计思路本身很好**——问题在执行层的分类准确性（见 P1-3），不是框架问题。

## 八、第二轮修复（2026-09-28 15 时，代码层：错误分类 + 本地校验）

本轮改了 `scripts/cli.mjs` 一个文件，两处改动：

1. **§3 错误分类错位修复**（`ERROR_PATTERNS`）：
   - `NO_RESULTS` 模式补充 `EMPTY_DATA` / `empty data` / `没找到数据` / `未找到数据` / `无数据` / `数据为空`；
   - `PARAM_VALIDATION_ERROR` 模式补充 `必须填`（命中后端纯文本报错如"observation或者[beginDate、endDate]必须填一个"）；
   - `TOOL_RUNTIME_ERROR` 模式补充 `inner payload is not valid JSON`，作为后端返回非 JSON 载荷且未命中上面两类时的兜底（不再掉进 NETWORK_ERROR）。
   - 复测结果：X07 周末空数据 → `NO_RESULTS` ✓；X13 未来日期 → `NO_RESULTS` ✓；A01 债券排名"没找到数据" → `NO_RESULTS` ✓（与 analytics.md 契约一致）；E06 缺时间范围 → `PARAM_VALIDATION_ERROR` ✓。
2. **§4 日期倒置本地拦截**（`validateBasicParams`）：对 `begin_date/end_date`、`begin/end`、`beginDate/endDate` 三对字段做先后校验（`LAST` 等别名自动跳过）。X14 日期倒置现在本地直接报 `PARAM_VALIDATION_ERROR` 并给出清晰中文提示，不再穿透到后端换一句"服务暂时不可用"。

回归复测：快照、K线、宏观取数 3 个正常用例全部通过。

继续在 `scripts/cli.mjs` 一个文件内完成：

1. **§1 返回代码一致性校验**（新增 `canonicalWindCode` / `checkReturnedWindCode`）：成功返回后，比对请求 `windcode` 与返回文本中的标的代码（数字段去前导零、后缀归一，避免 700.HK vs 0700.HK 误报）；不一致时在结果文本末尾追加 `[wind-cli 校验提示]` 警告。仅对带 `windcode` 参数的行情类工具（price/kline/quote）启用；`question` 类 NL 工具返回中可能合法包含其它证券代码（如基金重仓股），不做校验以免误报。复测：`999999.SH` → 正常返回但附警告"返回数据中的标的为 BJ.N……切勿当作 999999.BJ 的数据" ✓。
